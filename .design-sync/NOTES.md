# Design sync notes

Only what the next sync would get wrong without it. No dates, issue numbers or «after this sync» status: what a sync changed is in its PR, and the procedure below finds a lagging export every time. A note that stops being true is deleted, not amended.

- The Design System («Consuelo C Design System») is plain HTML + CSS, maintained by hand: `components/<group>/<group>.css`, `components/<group>/*.card.html` (first line `<!-- @dsCard … -->`), `components/README.md`, `assets/icons.svg`. There is no React bundle and no converter run.
- The app (`src/lib/components/*.svelte`, `src/app.css`, `static/icons.svg`) is the source of truth. A sync is a targeted edit: read the remote file, apply the code's change to it, upload only the files that changed. Never a wholesale replace.
- `get_file` content only reaches the conversation, not the disk, and the export (`../design/_ds/<folder>/`) can lag the remote. So always `get_file` the remote first. When it reads the same as the export (same line count and comment lines), copy the export; otherwise retype the remote and diff it against the export: the diff must show only the remote's newer edits. Then apply the edits with a script, so the final diff shows only them.
- The remote `assets/icons.svg` opens with a C2PA `<metadata>` block the server stamps on every upload: not part of the source. Build the upload from `static/icons.svg` plus `lock` after `help` (kept in the Design System for the navigation handoff, `uploads/ds-add-icons.md`, though the app doesn't use it yet); check the symbols against `static/icons.svg`, read it back after writing and count 27 symbols.
- To check a card before uploading, copy the export to the scratchpad, lay the staged files over it, and screenshot the card headless: `"/Applications/Brave Browser.app/Contents/MacOS/Brave Browser" --headless=new --allow-file-access-from-files --window-size=400,540 --screenshot=out.png file://…/card.html` (no Chrome on this machine).
- The desktop kits (`ui_kits/escritorio/index.html`, `pedido.html`, `impreso.html`) predate the shell: bring their sidebars in line with `navigation.card.html` when a sync touches those kits.
- Page-scoped in the app, named in the Design System: the Hint (`.hint`, in `horas/equipo/+page.svelte`; `feedback.css`), `.choice` (in `caja/+page.svelte` and `caja/registrar/+page.svelte`; `forms.css`) and the cash receipt's print overrides (in `caja/comprobante/+page@.svelte`; `print-sheet--quarter` in `print.css`). A sync of those pages edits those blocks. Extract the Hint when a second screen uses it, `.choice` when a third does.
