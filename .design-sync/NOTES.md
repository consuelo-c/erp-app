# Design sync notes

Only what the next sync would get wrong without it. No dates, issue numbers or «after this sync» status: what a sync changed is in its PR, and the procedure below finds a lagging export every time. A note that stops being true is deleted, not amended.

- The Design System («Consuelo C Design System») is plain HTML + CSS, maintained by hand: `components/<group>/<group>.css`, `components/<group>/*.card.html` (first line `<!-- @dsCard … -->`), `components/README.md`, `assets/icons.svg`. There is no React bundle and no converter run.
- The app (`src/lib/components/*.svelte`, `src/app.css`, `static/icons.svg`) is the source of truth. A sync is a targeted edit: read the remote file, apply the code's change to it, upload only the files that changed. Never a wholesale replace.
- `get_file` content only reaches the conversation, not the disk, and the export (`../design/_ds/<folder>/`) can lag the remote. So always `get_file` the remote first. When it reads the same as the export (same line count and comment lines), copy the export; otherwise retype the remote and diff it against the export: the diff must show only the remote's newer edits. Then apply the edits with a script, so the final diff shows only them.
- The remote `assets/icons.svg` opens with a C2PA `<metadata>` block the server stamps on every upload: not part of the source. Upload `static/icons.svg` as is, and the icons card (`components/icons/icons.card.html`) with a cell per symbol; read the sprite back after writing and check its symbols match `static/icons.svg`, one for one. While a phase opens, the remote sprite can hold an icon `static/icons.svg` doesn't have yet: don't upload the sprite until the app carries it.
- To check a card before uploading, copy the export to the scratchpad, lay the staged files over it, and screenshot the card headless: `"/Applications/Brave Browser.app/Contents/MacOS/Brave Browser" --headless=new --allow-file-access-from-files --window-size=500,540 --screenshot=out.png file://…/card.html` (no Chrome on this machine). Headless Brave lays out at least 500px wide: a narrower window crops the right edge.
- The desktop kits `ui_kits/escritorio/index.html` and `pedido.html` predate the shell: bring their sidebars in line with `navigation.card.html` when a sync touches those kits.
- Page-scoped in the app, named in the Design System: the Hint (`.hint`, in `horas/equipo/+page.svelte`; `feedback.css`), the cash receipt's print overrides (in `caja/comprobante/+page@.svelte`; `print-sheet--quarter` in `print.css`), the client cards (`.client`, in `pedidos/OrderForm.svelte`; `forms.css`), the search results (`.results`, in `pedidos/OrderLines.svelte`, `despachos/[id]/novedad/+page.svelte` and `inventario/+page.svelte`; `forms.css`) and the products checklist (`.line__check`, `.line--ticked`, in `despachos/[id]/+page.svelte`; `data.css`, its markup in the CSS comment, not in `components/README.md`). A sync of those pages edits those blocks. Extract the Hint when a second screen uses it.
- The `../design/ds-update-*.md` hand-offs are written from the screen designs and can lag the code: check each against the code (the menu against `DESTINATIONS` in `src/lib/navigation.ts`) and apply what the code says. A hand-off that opens a phase runs ahead of the code: check it against that phase's `planning.md` and `acceptance.md` instead, which win where they disagree. The menu shows up in `readme.md` (no-permission state, «Más» sheet, sidebar, destination icons), `components/README.md` (Sidebar, MenuList, Tabs), `navigation.card.html` and every kit's sidebar or bottom bar.
- The screen designs (the «ERP Consuelo C» project, files `2.1`–`2.15`, exported to `../design/`) are a regular project, not a design system: `DesignSync` can't list or write them. A sync that changes a screen updates the Design System here and hands the developer a prompt to redraw the screen in Claude Design.
